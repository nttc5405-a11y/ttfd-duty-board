# 成功大隊勤務看板

顯示當時段的人力、車輛編組與勤務類別，並整合 Google 行事曆行程。

---

## 這套東西怎麼運作

勤務資料鎖在需要登入的消防資訊系統（ttfd2.firemis.tw）裡。瀏覽器有安全機制，
**放在別的網站上的網頁沒辦法直接去抓它**。所以整套拆成三個角色：

```
[隊部電腦，人員已登入 ttfd2]
      │  點一下「更新看板」書籤
      │  在 ttfd2 自己的頁面裡讀取勤務表（同網域，合法）
      ▼
[Render 伺服器]  收下資料，存起來
      │
      ▼
[電視牆 / 手機 / 任何人開網址]   ← 不需要登入，自動更新
```

重點：**抓資料的動作發生在 ttfd2 自己的頁面裡**，所以拿得到；
看板端讀的是 Render 上的資料，所以不用登入。
帳號密碼全程不離開操作人員，不存在任何檔案或伺服器上。

**行事曆是另外一條完全獨立、不需要人操作的管線**：Google 日曆的
iCal 訂閱網址本身就是通行證，Render 伺服器自己每 12 小時去讀一次，
不用登入、不用書籤、不用隊部電腦開著。設定方式見下方部署步驟。

## 資料夾說明

| 位置 | 內容 |
|---|---|
| `web/` | 看板網頁本身。部署後電視牆和手機開的就是這個 |
| `server/` | Render 上的服務：收資料、供應資料、排程讀取 Google 行事曆 |
| `collector/` | 隊部電腦用的採集器（書籤／Tampermonkey 自動版）與探測腳本 |
| `docs/` | 給資訊單位或系統廠商的資料介面需求說明 |
| `勤務看板.html` | 單機版看板，雙擊即可開，供版面確認用 |

## 部署步驟

### 一、Render 建立服務

1. 把這個資料夾推上 GitHub
2. Render → New → Web Service → 連結該倉庫
3. 設定：
   - **Root Directory**：`server`
   - **Build Command**：`npm install`
   - **Start Command**：`npm start`
4. Environment 新增變數：
   - `PUSH_TOKEN`：自己取一串亂碼，採集器要用同一串
   - `ALLOW_ORIGIN`：`https://ttfd2.firemis.tw`
   - `CAL_ICS_URL_DAJI`（選填）：「大隊」來源日曆的 iCal 訂閱網址
   - `CAL_ICS_URL_YIXIAO`（選填）：「義消」來源日曆的 iCal 訂閱網址
   - `CAL_ICS_URL_JUBENBU`（選填）：「局本部」來源日曆的 iCal 訂閱網址

   行事曆這三個都是選填、互相獨立，沒設定就用看板內建的靜態快照。
   拿 iCal 訂閱網址的方式：Google 日曆網頁版 → 該日曆「⋮」→
   設定和共用 → 往下捲到「整合設定」→ 複製「私人網址（iCal 格式）」
   （若該日曆本身已設成公開，也可以用「公開網址」，不含密鑰、風險
   較低）。**這個網址等同密碼，只貼進 Render 的環境變數，不要貼進
   任何會進版本庫的檔案或對話紀錄。**

部署完成後會拿到一個網址，例如 `https://duty-board.onrender.com`。

> Render 免費方案在 15 分鐘無人存取時會休眠，再次開啟約需 30 秒喚醒。
> 電視牆整天開著就不會休眠。

### 二、隊部電腦設定採集器

依 `collector/collector-bookmarklet.txt` 的說明，把書籤加到瀏覽器書籤列。
第一次點擊時會詢問 Render 網址與 `PUSH_TOKEN`，輸入後記在該台電腦。

### 三、日常使用

1. 隊部電腦早上登入 ttfd2
2. 開到勤務表列表頁，按一次「查詢」
3. 點一下「更新勤務看板」書籤
4. 狀態視窗保持開著，之後每 5 分鐘自動更新
5. 系統授權過期時狀態視窗會提示，重新登入後再點一次書籤

## 開發者備註

`collector/collector.js` 是可讀版；改完後用下列指令重新產生書籤字串：

```bash
python collector/build.py collector/collector.js collector/_min.txt
```

不要用正則 `/\*.*?\*/` 移除區塊註解 —— 程式碼字串裡若含 `*/`（例如 `*/*`）
會被誤判為註解結尾，把中間整段吃掉。`build.py` 已改為逐行判斷。

## 長期目標

現行作法仍需人員每日登入一次。最終應請資訊單位或系統廠商開放唯讀資料介面，
屆時看板可完全自動更新、無人操作。需求內容見 `docs/資料介面需求說明.md`。
