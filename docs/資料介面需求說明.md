# 勤務看板資料介面需求說明

**提出單位**：臺東縣消防局成功大隊
**用途**：於大隊及所屬分隊建置勤務看板，即時顯示當時段人力、車輛編組與勤務類別
**文件版本**：2026-09-03

---

## 一、需求背景

大隊目前查詢當班人力與車輛編組，須逐一登入消防資訊系統（ttfd2.firemis.tw）、
逐單位點選勤務表。為便於隊部值班檯與電視牆即時掌握全大隊動態，
擬建置一面看板，自動彙整所屬 6 個單位的當時段勤務狀況。

看板本身**不需要任何操作功能，也不需要寫入權限**，只需要讀取既有勤務表資料。

## 二、需要的資料

即為系統中「勤務表列表」與「各單位勤務表」已呈現的內容，範圍如下：

### （一）單位當日概況（等同勤務表列表頁）
| 欄位 | 說明 |
|---|---|
| 日期 | 勤務日期 |
| 單位 | 單位名稱 |
| 主管 | 該日主管職稱與姓名 |
| 08-20 | 日間在班人數 |
| 20-08 | 夜間在班人數 |
| 上班人員 | 人員編號或姓名 |
| 更新時間 | 該筆勤務表最後更新時間 |

### （二）單位逐時編組（等同點進單一單位的勤務表）
| 欄位 | 說明 |
|---|---|
| 時間 | 每小時一列，08-09 至 07-08 共 24 列 |
| 值班 | 該時段值班人員 |
| 作戰編組 | 各車（如 91車、71車、16車、11、61車）之編組人員，欄位依各單位實際設定 |
| 備勤 | 該時段備勤人員 |
| 休息 | 該時段休息人員 |

### （三）當日勤務
| 欄位 | 說明 |
|---|---|
| 時間 | 勤務起訖，如 09-12 |
| 內容 | 勤務項目，如醫療訪視、水源查察 |
| 人員 | 執行人員 |
| 車輛 | 使用車輛 |
| 地點 | 執行地點 |

### （四）其他
- 附記（出勤原則）
- 假別名單：輪休、休假、半日勤務、公差假、補假、事病假

## 三、建議的提供方式（擇一即可）

### 方式 A：既有介面開放唯讀權杖（建議，改動最小）

經檢視，系統現行前端已透過下列介面取得本需求所需之全部資料：

| 介面 | 內容 | 對應本文第二節 |
|---|---|---|
| `/api/v2/shift/list` | 勤務表列表 | （一）單位當日概況 |
| `/api/v2/shift/{勤務表編號}` | 單一單位勤務表 | （二）逐時編組、（三）當日勤務、（四）附記與假別 |

**因此不需要新開發介面**，僅需就上述既有介面核發一組**唯讀專用權杖**，並限定：

- 僅可讀取，不得寫入或異動
- 資料範圍限本大隊及所屬分隊
- 可設定來源 IP 白名單，權杖由資訊單位核發並得隨時撤銷
- 建議另設較低的呼叫頻率上限（看板每 5 分鐘查詢一次即足夠）

**優點**：不需開發、資料即時、看板端不需任何人登入、權限可控可稽核。

### 方式 B：定時自動匯出檔案

系統既有「下載選取」匯出功能，請於此基礎上增加排程：

- 每日或每小時，自動將指定單位當日勤務表匯出為 JSON 或 CSV
- 存放至本局指定的共用位置（檔案伺服器或本局網頁空間）
- 檔名含日期，例如 `shift_成功大隊_20260903.json`

**優點**：不需新增介面，改動最小。
**限制**：資料非即時，更新頻率取決於排程間隔。

## 四、資安考量

1. **本需求為唯讀**，不涉及新增、修改、刪除任何勤務資料。
2. 資料範圍僅限**本大隊及所屬分隊**，不需其他大隊資料。
3. 內容為勤務編組與在班人力，屬內部作業資料；看板將設置於隊部內部，
   不對外公開，可依資訊單位要求限制存取來源。
4. 不需要、也請勿提供任何人員帳號密碼。權限請以系統核發之權杖或 IP 白名單管理。

## 五、過渡作法（介面開通前）

介面開通前，本大隊將於隊部值班電腦以人員登入後、由瀏覽器讀取自身畫面資料的方式
更新看板。此作法不涉及帳密外流，亦不對系統產生額外負擔，
惟需人員每日登入一次，故仍以第三節之正式介面為最終目標。
